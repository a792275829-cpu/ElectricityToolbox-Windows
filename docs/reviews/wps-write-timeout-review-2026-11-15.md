# WPS 写入无限等待与退出链路检查（2026-11-15）

## 现场与判断边界

- 用户反馈已发布最新版在另一台 Windows 电脑写入 14 个区域后不再前进，随后出现“等待其他 WPS 操作完成”；关闭被不可中断写入保护阻止，强制关闭后再打开显示“Python 任务服务已退出”，重启电脑后恢复。没有更多错误日志。
- 截图不能证明写入或保存完成，也不能定位远端接口、网络或浏览器的具体故障。
- 代码确认：页面就绪检查虽然有时间限制，实际 SDK 写入／保存／回读的 `page.evaluate` 之前没有给异步接口返回设置期限；UI 层 WPS 排队锁也无限等待。
- 界面退出后宿主会等待不可中断任务完成；任务一直不返回时旧宿主可能继续占据单实例入口，再次打开会访问已退出的 UI 进程。这条路径与截图一致，尚未在用户电脑确认。

## 修复

- SDK 操作增加 180 秒浏览器端异步期限，并报告区域处理、合并状态、保存、回读阶段。
- 超时明确标记“部分数据可能已经写入，结果待核对”，不自动重试；每次 SDK 等待恢复后及后续写入前检查期限，防止超时后恢复执行剩余写入。
- 写入提交后的导航／执行上下文丢失不再自动重放写入；操作前的明确 `WPS_API_NOT_READY` 检查仍可恢复。
- WPS 排队等待上限 30 秒，超时说明本次操作尚未提交，不释放原任务仍持有的锁。
- 宿主已进入界面退出后的任务清理阶段时，再次打开明确说明等待清理，不再尝试激活已经关闭的界面。保持正常写入的退出保护。

## 仍需说明

- 超时无法撤回已经发送给 WPS 的写入／保存请求；必须人工核对目标表格后决定是否重试。
