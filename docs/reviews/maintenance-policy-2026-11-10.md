# 维护流程约束整理（2026-11-10）

本轮按用户要求调整长期约定及对应流程门禁。开始时工作区已有多项未提交与未跟踪内容；
保留这些内容，只修改与本轮规则有关的段落、脚本和测试。不升级应用版本、不修改历史发行说明，
不提交推送、不创建标签或 Release。

## 规则调整

- 日常开发、提交同步、正式发行分阶段；main 作为集成主线，允许短期工作分支。
- Windows 发行号独立递增，上游 mac 版本与提交作为功能基线单独记录。
- 用户可见变化使用 Unreleased 草稿，发版时整理；取消条数要求，内部维护无需凑用户功能。
- 允许同步调用方、载荷和迁移逻辑后的目录重构；源码迁移重建虚拟环境，不修补其绝对路径。
- 长期规则、操作步骤和目录事实分别由 AGENTS、维护模型和结构地图负责。
- 正式公开前完成安装、升级与还原验收，公开后核对附件和下载链路。

## 脚本落实

- 新增 `tools/release_source.py`：正式构建拒绝脏工作区，记录提交与开发标记；不输出本地文件名。
- 正式 Windows 载荷仅导出已跟踪文件；载荷 manifest 与发行来源记录携带提交号。
- 显式开发构建允许本地改动，输出到 `dist/windows-development`，不生成正式补丁。
- 正式包拒绝本地业务工作簿种子；开发验证仍可显式传入。无标签 CI 安装包构建标记为开发包。
- 版本工具在写入前拒绝版本倒退与复用。
- 测试入口支持显式 `TOOLBOX_TEST_TAGS`，保留旧分类兼容；`--strict` 将整个模块缺依赖造成的跳过视为失败。
- CI full 使用 strict。模块内的平台 skip 仍需结合日志审阅，并未声称 strict 自动识别所有缺测。
- 归档清理默认预览，显式 `--apply` 执行；限制仓库归档树与时间戳快照，拒绝链接／重解析点。
- 清理失败不再吞掉异常，也不通过其他删除通道绕过守卫；构建不再自动移除会话注入。
- `-PruneArchive` 在构建前预览核对边界，成功后回收，失败现场保留；外部诊断归档不能用统一清理工具回收。

## 验证边界

本轮不重新生成安装包，不执行真实安装、覆盖升级、生产账号登录或业务数据上传。
临时夹具上的门禁与回收验证不能替代下次正式发行的安装及补丁验收。
源码边界固定到提交，不代表整个依赖下载链已达到逐字节可复现；旧测试启发式分类继续兼容，按实际需求迁移。
