# Rust 迁移范围

Windows 安装版保留原版 Tk 界面（现 16 个工具页）与操作流程；第 16 个工具「私有数据批量上传」为 Node 实现，不接入 Rust 后端。Rust 承担下列默认后端路径；Python 适配层负责界面、引擎调用、结果包装与业务回读验证。

| 模块 | Rust 执行范围 | 保留的引擎与适配 |
| --- | --- | --- |
| 500kV 断面 | 节点与别名匹配、跨表去重、拓扑、Decimal 均值、区间与汇总、分类 | 工作簿入口、图表与报告渲染 |
| 交易分析与电量汇总 | 新旧表解析、报价分段、机组与公司聚合、偏差与排名、汇总数据转换 | HTML、工作簿样式与 Tk |
| 电价预测 | 日期与粒度整理、标签、滞后与滚动特征、训练划分、基线和评价 | 数据源读取、节假日来源、sklearn 模型训练与输出 |
| PDF 图表 | 网格、坐标轴、柱形与颜色、分类和容量、申报归一化与校准 | PDFium/pdfplumber、系统 OCR、Pillow、文档输出 |

## 兼容与验证口径

中文字段、日期偏移、工作表与输出顺序沿用原实现。断面筛选沿用“累计至少四个符合条件的时段”，连续窗口仅用于展示。金额与 Decimal 口径不变。预测浮点归约允许 `rtol=atol=1e-10`，NaN 位置、列顺序、类型、日期与目标值严格一致。

`TOOLBOX_DOMAIN_BACKEND=python|rust|auto` 可选择原实现、严格原生或自动模式；未设置时继承 `TOOLBOX_XLSX_BACKEND`。自动模式在纯读取/计算路径不可用时保留兼容回退；严格原生模式上报错误。已经开始原生写入的错误不会自动切换引擎重试。

复杂合并样式、数组/数据表公式或 ISO 日期等尚不支持的模板由适配层明确交还原引擎。市场表样式仍由 openpyxl 序列化，Rust 负责目标 XML 与 ZIP 写入。模型训练与浏览器引擎依赖仍需随安装包携带，因此本次迁移不等于移除 Python 或大幅缩小安装包。

## 性能记录

同一个包内 Python 3.12.16／同一份源码，完成 ping/catalog 初始化后空闲采样五次：原 Python 服务的工作集中位数 25.344 MiB，Rust 服务为 5.184 MiB；私有提交分别为 17.848／0.781 MiB。这里只统计任务服务进程，不包含 Tk、业务工作进程或短时兼容进程，不能据此推断整个应用的内存降幅。

预测测试使用 180 天、17,280 行、111 个特征，预热一次后交错测量五次。Python 中位数 0.181133 秒，Rust release 二进制传输中位数 0.178067 秒，结果处于测量波动内，不能视为明显加速。二进制传输消除了大矩阵逐值 JSON 的额外开销。

完整任务复用惰性 Rust 进程，缓存限于任务范围；数值矩阵和图像使用紧凑传输。各业务性能须按实际输入衡量，不以 Rust 语言本身推断加速比例。

验证使用临时合成工作簿、图像与任务进程，核对完整值、关键格式、公式和非目标 ZIP 内容。未使用个人凭据、生产写入或真实上传。Windows 可实际运行与安装验证；本机无法执行 macOS 应用与打包验收。
