## Constraints

Back up real user configuration/data before an actual local update. Close only the identified idle toolbox through its normal quit command; do not terminate unrelated processes or persistent user browsers. The host's global single-instance lock means isolated host acceptance must run while the real host is closed, then restore the user's window. Do not declare live browser profile bytes unchanged. Keep all private fixtures/logs/builds/credentials outside Git. Never overwrite earlier release assets or merge the full source into main.

## Expected evidence

Record exact patch/index bytes versus full-installer bytes, HTTP assets, helper state, old/new host and Tk processes, complete program hashes, unchanged runtime file identity, configuration markers and Excel readback. Windows 10/macOS real-machine limitations must remain explicit. Successful source tests alone do not authorize a release without installer and upgrade acceptance.

## Validation ruling

The post-publication network test will upgrade the real, verified 0.1.29 installation directly. The isolated prepublication test already covers configuration/Excel fixtures, complete restore and rollback boundaries; repeating another full isolated 0.1.29 installation after publication adds no necessary coverage. The actual installation's complete 16,764-entry tree has independently matched the genuine 0.1.29 baseline. Its live browser profiles stay outside the install root and are excluded from byte-equality claims.
