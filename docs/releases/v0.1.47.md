# Windows v0.1.47 发行验收记录

用户可见变化以根目录 `CHANGELOG.md` 为唯一来源；本文件记录本轮的验收范围、环境与结果，
实现细节和验证证据在此留档，不改写已发布版本的历史记录。

## 范围

- 早报机组启停：`每日生产经营情况汇报自动生成工具/scripts/generate_red_marked_report.py` 新增
  `_day_ahead_unit_transitions`，按「汕头」「海门」工作表的机组号与「日前电量」表头读取 0:00 至 23:00 的
  24 点电量；24 点全部有效且正值与零之间只切换一次时，以「运行转备用」/「备用转运行」覆盖「基础信息」的
  机组状态，东莞与清远继续沿用基础信息。`fill_startup_status` 对含转换的段落不再简写为「与前一日运行方式一致」。
- 日报价格口径：`compare_strategy_day_ahead_price` 用报告日与前一日「快报（日前）」A41 的全省日前均价
  重算现货交易策略段环比（`Decimal` 两位、`ROUND_HALF_UP`，含「环比持平」）；日清分「日前市场」直接引用
  清分日 A41 原文的全省日前出清均价及环比，删除原「全省节点均价（日更）」96 点平均与 `find_first_column_row`
  旁路；实时均价仍按 `快报` 实时简析替换。
- WPS 写入：`wps自动/wps_excel_to_kdocs_gui.py` 删除逐区域 `range.MergeCells` 等待及其返回字段，
  批量写入不再因未使用的合并状态查询触发接口超时。
- 测试：`test_unit_status`（新增 `DayAheadUnitStatusTests` 与实际曲线样本）、`test_report_text`
  （改为各自快报取数）、`test_wps_api_recovery`（对齐去掉 `mergeCells` 的脚本）。
- 诊断留档：`docs/reviews/report-unit-status-2026-11-20.md`。
- 发行产物：`ElectricityToolbox_0.1.47_windows_x64_setup.exe`、同名 `.sha256`、`updates-0.1.47/`
  内的增量补丁与 `windows-update-manifest.json` 及其摘要、`source-0.1.47.json`。

## 环境

- Windows 10 / 11 x64；Windows PowerShell 用于构建入口，Git Bash 用于只读检查。
- `.python-version` 为 3.11.15；独立 CPython `.toolbox/standalone-python` 与测试用 `.venv/Scripts/python.exe`
  均为 3.11.15。
- Node `v22.22.2`；Rust / cargo `1.99.1` 位于 `%USERPROFILE%\.cargo\bin`。
- 旧版基线：本地留存的 `ElectricityToolbox_0.1.46_windows_x64_setup.exe`，用于覆盖升级与增量补丁还原。
- 复用 v0.1.46 构建后的 release 缓存；测试使用统一入口的隔离数据目录；不执行生产账号登录、
  真实上传或业务工作簿写入。

## 结果与证据（发行前检查）

- `version.py set 0.1.47` 输出 `v0.1.47`；`version.py check --tag v0.1.47 --require-notes` 输出 `v0.1.47`，
  package.json、package-lock.json、tauri.conf.json、Cargo.toml、Cargo.lock 五处一致。
  `version.py set` 仍会保留 `[Unreleased]` 草稿，已按约定手工移除草稿段。
- `git -c core.whitespace=cr-at-eol diff --check` 通过；未引入凭据、登录态、业务工作簿或构建产物。
- 改动按主题拆为三个提交（机组启停、日前均价口径、WPS 写入），版本与日志作为发布提交，便于单独回溯。
- `tools/run_tests.py full --strict`：**151 / 155 通过、跳过 0，用时 659.2 s**。失败的 4 个模块
  `desktop:test_windows_delta`、`test_windows_update`、`test_windows_update_build`、`test_windows_update_helper`
  与 0.1.46 同一现象：会话注入的批量删除守卫在删文件时以 `SystemExit: 1` 中断，不是断言失败。
- 未绕过守卫：4 个模块按单次工具调用分别复跑，**15/15、23/23、8/8、18/18** 全部通过。
- 本轮相关模块在全量中的结果：`report:test_unit_status` 12/12、`report:test_report_text` 20/20。
  `toolbox:test_wps_api_recovery` 在全量轮次中未单独留档，按单次调用复跑为 **26/26 通过**（11.8 s）。
