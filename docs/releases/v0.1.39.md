# Windows v0.1.39 发行验收记录

用户可见变化以根目录 `CHANGELOG.md` 为唯一来源；本文件记录本轮的验收范围、环境与结果，
实现细节和验证证据在此留档，不改写已发布版本的历史记录。

## 范围

- 源码：`main` 上 v0.1.38 之后的 4 个修改文件：WPS 写入工具的登录端口与界面布局实现、两份针对性测试，以及本轮的版本元数据、更新日志与发行记录改动。
- 用户可见变化：WPS 登录误连其他工作区后台浏览器时改为自动选择并保存独立端口；配置编辑窗口按显示缩放增大，列表行距与列宽调整，配置列表在内部滚动，不再撑宽主页面。
- 发行产物：`ElectricityToolbox_0.1.39_windows_x64_setup.exe`、同名 `.sha256`、`updates-0.1.39/` 内的增量补丁与 `windows-update-manifest.json` 及其摘要、`source-0.1.39.json`。

## 环境

- Windows 10 / 11 x64；Windows PowerShell 5.1 用于构建入口，Git Bash 用于只读检查。
- `.python-version` 为 3.11.15；独立 CPython `.toolbox/standalone-python` 为 3.11.15 x64，测试用 `.venv/Scripts/python.exe`，三者一致。
- Rust / cargo 1.99.1、Node 22.22.2、NSIS makensis。
- 旧版基线：本地留存的 `ElectricityToolbox_0.1.37_windows_x64_setup.exe`（325,703,186 字节）与 `ElectricityToolbox_0.1.38_windows_x64_setup.exe`（325,743,730 字节）。
- 复用 v0.1.38 构建后的 release 缓存，不重复清理；测试使用统一入口的隔离数据目录；不执行生产账号登录、真实上传或业务工作簿写入。

## 结果与证据（发行前检查）

- `version.py check --tag v0.1.39 --require-notes` 输出 `v0.1.39`；package.json、tauri.conf.json、package-lock.json、Cargo.toml、Cargo.lock 五处版本一致。发布说明由 `version.py check --release-notes` 导出到 `dist/v0.1.39-release-notes.md`（1,845 字节），内容为本版 2 条变更与通用安装说明。
- `git -c core.whitespace=cr-at-eol diff --check` 通过。仓库元数据文件本身为 CRLF，按仓库既有换行口径复核后确认没有真正的行尾空格；待提交 11 个文件均为源码、测试、文档与版本元数据，无凭据、登录态、业务工作簿或构建产物。
- `tools/run_tests.py full --strict`：155 个模块中 151 个通过、跳过 0，用时 736.0 秒。4 个失败模块为 `test_windows_delta`、`test_windows_update`、`test_windows_update_build`、`test_windows_update_helper`，均在 desktop 组；traceback 全部指向会话注入的 `sitecustomize.py::_check_bulk_delete_guard` 拦截 `windows_delta.py` 的临时目录清理与 `path.unlink()`。这是首次全量运行的真实结果，不表述为一次性全绿。
- 对这 4 个模块用统一入口 `--module` 集中复跑：4/4 通过、跳过 0，用时 64.5 秒。失败来自守卫触发的批量删除阈值而非代码回归；未因复跑通过而改写首次全量结果，也未重复整轮。本轮 `test_rust_service` 在全量中正常通过。
- Rust：`cargo test --manifest-path native/price-xlsx/Cargo.toml --locked` 13/13 通过；`cargo test --manifest-path desktop/src-tauri/Cargo.toml --locked` 2/2 通过（debug 编译 1 分 45 秒）。复用已清除旧绝对路径的缓存，未出现 build script 读取插件权限文件失败。

## 隔离安装验收结果

验收复用 v0.1.38 验收脚本的实现（`dist/acceptance_0_1_39.py` 仅替换版本与产物路径），在 Git 忽略的 `dist/acceptance-0.1.39/` 隔离目录执行；HKCU 注册表值先保存后恢复，不涉及用户日常安装目录。

- 全新安装：回读版本 0.1.39，清单 14,941 项；主程序、内置 Python、载荷清单与 Rust 服务均在位。
- 覆盖升级：先装 0.1.38（回读 0.1.38），写入 `state/acceptance-marker.json` 模拟用户数据，再用完整包覆盖；回读 0.1.39，标记文件内容与哈希未变。**清单与全新安装逐项完全一致**（仅全新安装独有 0 项、仅升级目录独有 0 项、内容差异 0 项）。
- 补丁实际还原：以真实 0.1.38 安装副本为基准，`clone_installation` + `apply_patch(0.1.38→0.1.39)` 后回读 0.1.39，清单与全新安装逐项完全一致。
- 安装版运行时：内置 Python 3.11.15 成功导入 tkinter／openpyxl／pandas／numpy 并实际创建、销毁 Tk 窗口（`TK=OK`、`DEPS=OK`）；Rust 服务实际启动，输出 `service-ready`（protocol 3）与 `service-closed`。
- 三处安装目录的 `payload/manifest.json` 版本均为 0.1.39，来源提交均为 `1224b5d…`、`dirty=false`。
- 主程序 Authenticode 状态为 `NotSigned`（与既有发行一致，项目未做代码签名）；`state/installed.json` 由首次真实运行生成，静默安装目录内未能回读，改以三处 `payload/manifest.json` 回读版本。
