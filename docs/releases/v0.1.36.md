# Windows v0.1.36 历史验证记录

以下内容从整改前的 CHANGELOG 原样归档，用于追溯当时的实现、验证与限制；不代表本轮重新执行，也不作为当前操作说明。
已发布安装包和 Release 内容不作修改。当前用户可见变更摘要仍以根目录 CHANGELOG 为唯一来源。

## [0.1.36] - 2026-11-10

- 加固南方分公司电力市场日报选文件后的日期识别：将模块导入、Excel 读取及整本解析回退移到独立进程，避免后台 Python 线程仍与 Tk 共享 GIL 和模块加载锁；移除同进程预热。读取进程超过 25 秒自动终止并提示原因；界面轮询最多等待 30 秒，切换文件和关闭页面会取消旧轮询，过期结果不再覆盖新选择，同时限制并发读取数量。识别开始立即清除旧日期和补录数据；点击生成或手动填写时只检查识别状态，不再同步重读文件。
- 验证：8 项新增回归与 6 项既有日报 UI 测试通过，覆盖慢读取下界面事件仍响应、超时、连续换文件、关闭页面、识别中操作、子进程异常、损坏文件及 A6 优先于 A2/文件名；7 份本机真实收益表均正确识别（独立进程含启动约 0.60–0.73 秒）；源码启动自检 TOOLBOX_SMOKE=OK。另一台电脑尚待安装本版更新后复测。
- 修复打包在 Agent 会话中反复中断：会话会把批量删除守卫注入所有子进程，`prepare_payload.py` 清空 `payload/app`、`npm ci` 清空 `node_modules`、`build_updates.py` 删除补丁还原目录三处先后被 fail-closed 掐断。现改为两层处理——`build.ps1` 先用新增的 `build_env.ps1`／`Reset-BuildEnvironment` 只移除指向 `vendor\shim` 的 `NODE_OPTIONS`／`PYTHONPATH`／`PATH` 条目和 `CODEBUDDY_SAFE_DELETE_BULK_GUARD`，还原成人工终端环境（`-KeepGuard` 可保留）；生成目录则改为改名归档到 `dist/build-archive/<时间戳>/` 后重建，不再原地删除。
- 新增 `packaging/windows/prune_build_archive.py` 统一回收归档：默认保留最近 1 份，先 robocopy 空目录镜像再删空骨架，可处理上万文件与超长路径；`build.ps1 -PruneArchive` 构建成功后自动调用，`-DryRun` 只打印归档计划不改文件。`packaging/windows/README.md` 与 `AGENTS.md` 补充构建机清理约定。
- 验证：`prepare_payload.py --dry-run` 输出归档目标且未改动文件；连续两次真实重建成功（第二次走归档路径，app 63.1 MB、runtime/python 410.1 MB），`PAYLOAD_FRESH=OK`、payload 692 个受管文件；`npm ci` 在 `node_modules` 归档后重装 50 个包并恢复 `tauri` 命令；修复前全量 `build.ps1` 在补丁还原目录处第 3 次被拦，加入环境还原后 `build_updates.py` 一次产出 0.1.32/0.1.33/0.1.34 三条直达补丁（3,678,576 / 5,074,260 / 5,142,324 字节）且全部通过还原校验；`prune_build_archive.py --keep 1` 实际回收 473.1 MB 与 450.0 MB 两份快照、保留 1 份；新增 10 项归档与回收单测通过。该轮构建产物仅作验证，未覆盖当时已发布的 0.1.35 资产。
- 修复增量更新回退后无从定位：补丁被拒时把原因写入 `state/windows-update-fallback.json`（当前版本、目标版本、原因、时间），更新窗口显示「完整更新（补丁不适用）」并附具体原因；上一轮增量安装已失败并回滚的目标版本，本次直接使用完整安装包时同样带出当时的失败原因。此前 `fallback_reason` 只存在内存对象里，现场只能看到「先下载补丁、再全量下载」。
- 新增 `packaging/windows/diagnose_delta.py`：对照已发布补丁基线检查本机安装目录，列出缺失、多余、内容不符的文件，并判定补丁校验是否会失败，用于定位回退完整包的具体文件。
- 验证：更新器／增量／Windows 增量 53 项单测通过（15 项按平台跳过）；更新界面 22 项通过，新增用例覆盖回退原因显示与空值/Mock 不显示；诊断脚本在构造目录上实测能正确区分可回收 `__pycache__/*.pyc` 与清单外文件。
- 继续修复南方分公司电力市场日报识别报告日期仍慢、界面卡住：上一版只读流式通道只接受「新快报」工作表，而加入 D 日全天出清明细的现行工作簿日报表名为「新」，因此每次识别都退回整本工作簿的完整解析（本机 2.4–2.6 s），纯 Python 解析在后台线程里持续占用 GIL，窗口表现为假死。现只读通道按「新快报→新别名」顺序选表，并用流式条件（max_column≥17、A4 日前简析、前 200 行实时简析）确认表身份；「快报*」旧版、A4 为空需按收益模板识别的表，以及只读通道读不了的情况一律交回完整解析，日期口径（A6→A2→A7→文件名）、选表顺序与错误文案不变。工具箱页面同时改为打开即在后台预热日期读取模块，首次选文件不再额外等模块导入。
- 验证：真实出清工作簿（1.19 MB，含 D 日全天出清明细）识别由 2.4–2.6 s 降至 0.18–0.37 s；工具箱页面实测「选中文件→日期显示」0.23 s（含预热），冷启动首次 1.65 s→0.20 s；日报模块 52 项＋26 项相关回归、日报页面 6 项 UI 测试通过，新增「新别名不走完整解析」「A4 为空仍走完整解析」2 项用例；源码启动自检 `TOOLBOX_SMOKE=OK`。
