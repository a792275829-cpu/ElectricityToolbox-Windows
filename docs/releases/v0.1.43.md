# Windows v0.1.43 发行验收记录

用户可见变化以根目录 `CHANGELOG.md` 为唯一来源；本文件记录本轮的验收范围、环境与结果，
实现细节和验证证据在此留档，不改写已发布版本的历史记录。

## 范围

- 源码：`main` 上 v0.1.42 之后的 2 个业务文件——`wps自动/wps_excel_to_kdocs_gui.py`（WPS 自动登录状态检查不再计入退出保护）与 `每日生产经营情况汇报自动生成工具/scripts/generate_red_marked_report.py`（早报均价来源、电量未更新标注、天气段落保留、宽表不再阻断整簿读取）。
- 测试：7 个模块扩充用例，新增“空闲时关闭／重启通过真实退出检查”“状态检查不阻塞关闭”“宽表不阻断报告表”“宽表仍拒绝真正读取”“天气不变不删手写内容”“均价取数失败降级”等回归。
- 文档：新增 4 份评审记录（`docs/reviews/recovery-needed-2026-11-16.md`、`report-fix-2026-11-17.md`、`report-safety-review-2026-11-16.md`、`windows-suggestions-review-2026-11-16.md`），其中后两份对应 2026-11-16 误回退中丢失、尚未重做的改动，已在文首标注“未落地”，不作已发行能力。
- 用户可见变化：`CHANGELOG.md` 的 0.1.43 条目共 3 条，`[Unreleased]` 草稿已整理并移除。
- 发行产物：`ElectricityToolbox_0.1.43_windows_x64_setup.exe`、同名 `.sha256`、`updates-0.1.43/` 内的增量补丁与 `windows-update-manifest.json` 及其摘要、`source-0.1.43.json`。

## 环境

- Windows 10 / 11 x64；Windows PowerShell 用于构建入口，Git Bash 用于只读检查。
- `.python-version` 为 3.11.15；独立 CPython `.toolbox/standalone-python` 与测试用 `.venv/Scripts/python.exe` 均为 3.11.15。
- Rust / cargo 位于 `%USERPROFILE%\.cargo\bin`（未加入 Git Bash 的 PATH，测试用绝对路径调用）。
- 旧版基线：本地留存的 `ElectricityToolbox_0.1.42_windows_x64_setup.exe`，用于覆盖升级与增量补丁还原。
- 复用 v0.1.42 构建后的 release 缓存；测试使用统一入口的隔离数据目录；不执行生产账号登录、真实上传或业务工作簿写入。

- `tools/run_tests.py full --strict`：**150 / 154 通过、跳过 0，用时 561.7 秒**。失败 4 个模块 `desktop:test_windows_delta`、`test_windows_update`、`test_windows_update_build`、`test_windows_update_helper` 均为会话注入的批量删除守卫在同一工具调用内累计 50 次删除后以 `SystemExit: 1` 中断（`_check_bulk_delete_guard` → `_exit_bulk_guard_control`），不是断言失败，也不来自本轮改动。
- 未绕过守卫：改用 `--group desktop` 在独立进程（守卫计数重置）复跑，**29 / 29 模块通过、166.3 秒、跳过 0**，含上述 4 个模块（分别 15、23、8、18 个用例）；单独复跑这 4 个模块亦为 15/15、23/23、8/8、18/18。
- 全量运行期间 `report` 组真实结果：`test_report_text` 14/14、`test_daily_clearing_fill` 17/17、`test_online_energy` 9/9、`test_workbook_dates` 8/8，覆盖本轮早报修改。
- `start_source_test.ps1 -Smoke` 输出 `TOOLBOX_SMOKE=OK`、`TOOLBOX_DEPS=OK`。
- Rust：`cargo test --manifest-path native/price-xlsx/Cargo.toml --locked` **13/13 通过**；`cargo test --manifest-path desktop/src-tauri/Cargo.toml --locked` **3/3 通过**。

## 构建与产物

- 本轮先用 `packaging/windows/build.ps1 -PythonRoot .toolbox/standalone-python` 启动构建，在载荷重建阶段 2 分钟处被终止且无异常输出；复现确认是当前会话的后台命令在 120 秒被强制结束（同口径的 150 秒睡眠任务同样在第 121 秒被终止），不是构建失败。
- 改为按 `build.ps1` 原有顺序逐条执行同样的脚本与命令（`prepare_payload.py` → `verify_payload.py` → 归档 `node_modules` → `npm ci` → `npm run build -- --bundles nsis` → 复制安装包与摘要 → `release_source.py` → `build_updates.py`），编排方式变化不影响产物口径；脚本路径 `dist/build-0.1.43.sh` 与日志 `dist/build-0.1.43.log`（均在 Git 忽略目录）。
- 载荷：归档旧 `app`（51.5 MB）与内置 `python`（410.1 MB），`Windows payload ready: 690 managed files`、`PAYLOAD_FRESH=OK`（版本 0.1.43、helper 与 Rust 源码一致、运行时 Python 3.11.15）。
- NSIS / LZMA 打包产出 `电力工具箱_0.1.43_x64-setup.exe`（310.63 MiB），复制为 `ElectricityToolbox_0.1.43_windows_x64_setup.exe`，**325,724,286 字节**，SHA-256 `ec7292b6638f1bfbfecfd8a70568547d9f1d92e136a48f7c2de85705f30ab1c6`；`source-0.1.43.json` 与载荷 `manifest.json` 的来源均为 `{commit: 3c4a14a, development: false, dirty: false}`，载荷版本 0.1.43、690 项。
- 全流程退出码 `BUILD_EXIT=0`，本轮未再出现 0.1.42 的批量删除守卫拦截。
- `updates-0.1.43/` 含 0.1.42→0.1.43 补丁 **2,911,592 字节**（`9b4ca2b2…ad0cc1`）及摘要、`windows-update-manifest.json`（2,311 字节，`63bf8329…e45877a`）及摘要；索引共 **5 条直达路径**，以 0.1.42→0.1.43 为主链，其余沿用既有链式路径。
