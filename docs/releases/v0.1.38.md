## 结果与证据（发行前检查）

- `version.py check --tag v0.1.38 --require-notes` 输出 `v0.1.38`；package.json、tauri.conf.json、package-lock.json、Cargo.toml、Cargo.lock 五处版本一致。发布说明由 `version.py check --release-notes` 导出到 `dist/v0.1.38-release-notes.md`。
- `git -c core.whitespace=cr-at-eol diff --check` 通过。仓库元数据文件本身为 CRLF，按仓库既有换行口径复核后确认没有真正的行尾空格。
- `tools/run_tests.py full --strict`：155 个模块中 151 个通过、跳过 0，用时 646.0 秒。4 个失败模块为 `test_windows_delta`、`test_windows_update`、`test_windows_update_build`、`test_windows_update_helper`，均在 desktop 组；traceback 全部指向会话注入的 `sitecustomize.py::_check_bulk_delete_guard` 拦截 `windows_delta.py` 的临时目录清理与 `path.unlink()`。这是首次全量运行的真实结果，不表述为一次性全绿。
- 对这 4 个模块用统一入口 `--module` 集中复跑：4/4 通过、跳过 0，用时 59.2 秒。失败来自守卫触发的批量删除阈值而非代码回归；未因复跑通过而改写首次全量结果，也未重复整轮。与 v0.1.37 相比，本轮 `test_rust_service` 正常通过（未出现并发临时文件占用）。
- Rust：`cargo test --manifest-path native/price-xlsx/Cargo.toml --locked` 13/13 通过；`cargo test --manifest-path desktop/src-tauri/Cargo.toml --locked` 2/2 通过。本轮复用上一轮已清除旧绝对路径的缓存，未再出现 build script 读取插件权限文件失败。
- `start_source_test.ps1 -Smoke` 输出 `TOOLBOX_SMOKE=OK`、`TOOLBOX_DEPS=OK`。

## 隔离安装验收结果

验收复用 `windows_delta` 的安装、清单与补丁模块，在 Git 忽略的 `dist/acceptance-0.1.38/` 隔离目录执行；HKCU 注册表值先保存后恢复，不涉及用户日常安装目录。

- 全新安装：回读版本 0.1.38，清单 14,941 项；主程序、内置 Python、载荷清单与 Rust 服务均在位。
- 覆盖升级：先装 0.1.37（回读 0.1.37），写入 `state/acceptance-marker.json` 模拟用户数据，再用完整包覆盖；回读 0.1.38，标记文件内容与哈希未变。**清单与全新安装逐项完全一致**（仅全新安装独有 0 项、仅升级目录独有 0 项、内容差异 0 项）。v0.1.37 验收中出现的 `payload/runtime/ms-playwright/.links/…` 缓存标记残留本轮未复现。
- 补丁实际还原：以真实 0.1.37 安装副本为基准，`clone_installation` + `apply_patch(0.1.37→0.1.38)` 后回读 0.1.38，清单与全新安装逐项完全一致。
- 安装版运行时：内置 Python 3.11.15 成功导入 tkinter／openpyxl／pandas／numpy 并实际创建、销毁 Tk 窗口（`TK=OK`）；Rust 服务实际启动，输出 `service-ready`（protocol 3）与 `service-closed`。
- 三处安装目录的 `payload/manifest.json` 版本均为 0.1.38，来源提交均为 `978d894…`。
- 主程序 Authenticode 状态为 `NotSigned`（与既有发行一致，项目未做代码签名）；`state/installed.json` 由首次真实运行生成，静默安装目录内未回读到，改以三处 `payload/manifest.json` 回读版本。
