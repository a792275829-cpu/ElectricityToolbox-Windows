# Windows v0.1.46 发行验收记录

用户可见变化以根目录 `CHANGELOG.md` 为唯一来源；本文件记录本轮的验收范围、环境与结果，
实现细节和验证证据在此留档，不改写已发布版本的历史记录。

## 范围

- 新增模块 `toolbox_cancellation.py`：`CancellationToken` / `TaskCancelled` / `checkpoint()` 与
  `TOOLBOX_TASK_CANCEL_FILE` 标记文件的统一入口，`COOPERATIVE_TOOLS` 声明参与协作取消的工具。
- 宿主侧：`native/price-xlsx/src/service_main.rs` 为任务记录 `cooperative`，协作任务改发取消标记
  而不是立即终止进程；`desktop/python/service_compat.py` 在 `__prepare_start` 下发该标志，
  `desktop/python/task_worker.py` 以退出码 130 与 `TaskCancelled` 汇报取消，
  `desktop/python/service_bridge.py` 在父进程断连时只对非协作任务发出取消，等待协作任务收尾。
- 工具箱侧：`toolbox/tasks/models.py` 改为复用共享令牌，`tasks/engine.py` 与 `tasks/process.py`
  支持协作模式（等待当前步骤收尾、保留输出读取、清理临时标记），`tasks/process.py` 新增取消标记文件传递；
  `ui_tasks.py` 的 WPS 队列等待改为可中断，`toolbox/service.py` 记录协作任务并新增 `cancel_on_disconnect`，
  `cancellable` 统一返回真。
- 业务脚本检查点：`交易系统信息更新`、`功率调整收益统计表更新`、`市场表更新`、`现货价格更新`、
  `集团每日上传`、`上网电量抓取`（含登录锁等待）、`广东运行日报PDF解析`、`电量汇总工具`、
  `private-data-uploader-tool`（`upload-private-data.mjs`、`auth-lock.mjs`）与
  `wps自动/wps_excel_to_kdocs_gui.py`（配置准备、浏览器就绪等待、在线读取、写入与回读）。
- WPS 写入页：新增「取消任务」按钮，工具栏文案换行阈值随之调整。
- 上网电量：`export_online_energy.py` 的倍率改为按十进制换算（`Decimal`），避免二进制长尾；
  WPS 读取旧版上网电量汇总时，只对「清远 实际上网电量（万千瓦时）」区块内的数值清理浮点尾差。
- 测试：`desktop/tests/python/` 3 个模块与 `电力工具箱/tests/` 5 个模块调整口径并补回归；
  `test_tasks` 新增协作取消用例（等待当前步骤、清理、不进入下一步），`test_wps_batch_reads` 新增尾差清理用例，
  `test_rust_service` 覆盖协作取消与断连等待。
- 用户可见变化：`CHANGELOG.md` 的 0.1.46 条目共 2 条，`[Unreleased]` 草稿已整理并移除。
- 发行产物：`ElectricityToolbox_0.1.46_windows_x64_setup.exe`、同名 `.sha256`、`updates-0.1.46/`
  内的增量补丁与 `windows-update-manifest.json` 及其摘要、`source-0.1.46.json`。

## 环境

- Windows 10 / 11 x64；Windows PowerShell 用于构建入口，Git Bash 用于只读检查。
- `.python-version` 为 3.11.15；独立 CPython `.toolbox/standalone-python` 与测试用 `.venv/Scripts/python.exe`
  均为 3.11.15。
- Rust / cargo 位于 `%USERPROFILE%\.cargo\bin`（未加入 Git Bash 的 PATH，测试用绝对路径调用）。
- 旧版基线：本地留存的 `ElectricityToolbox_0.1.45_windows_x64_setup.exe`，用于覆盖升级与增量补丁还原。
- 复用 v0.1.45 构建后的 release 缓存；测试使用统一入口的隔离数据目录；不执行生产账号登录、
  真实上传或业务工作簿写入。

## 结果与证据（发行前检查）

- `version.py check --tag v0.1.46 --require-notes` 输出 `v0.1.46`，package.json、package-lock.json、
  tauri.conf.json、Cargo.toml、Cargo.lock 五处一致。`version.py set` 仍会保留 `[Unreleased]` 草稿，
  已按约定手工移除草稿段。
- `git -c core.whitespace=cr-at-eol diff --check` 通过；待提交 53 个文件（+641 / −176），
  含 1 个新增模块，其余为源码、测试与版本元数据，无凭据、登录态、业务工作簿或构建产物。
- `tools/run_tests.py full --strict`：**151 / 155 通过、跳过 0，用时 592.3 秒**。失败的 4 个模块
  `desktop:test_windows_delta`、`test_windows_update`、`test_windows_update_build`、`test_windows_update_helper`
  均为会话注入的批量删除守卫在删文件时以 `SystemExit: 1` 中断（`_check_bulk_delete_guard`），
  不是断言失败，与本轮改动无关。
- 未绕过守卫：4 个模块按工具调用分别复跑，**15/15、23/23、8/8、18/18** 全部通过。
  同一 shell 内串联调用会共享守卫计数、仍然失败，已按单次调用逐个复跑。
- 本轮相关模块在全量中的结果：`toolbox:test_tasks` 14/14（另 3 项为 POSIX 进程组语义用例，
  在 Windows 上按设计跳过，Windows 后代进程由 `desktop:test_rust_service` 覆盖）、
  `toolbox:test_log_console` 25/25、`toolbox:test_online_energy_output` 32/32、
  `toolbox:test_wps_batch_reads` 5/5、`toolbox:test_review_fixes` 4/4、
  `desktop:test_rust_service` 15/15、`desktop:test_service` 17/17。
- `start_source_test.ps1 -Smoke` 输出 `TOOLBOX_DEPS=OK`、`TOOLBOX_SMOKE=OK`。
- Rust：`cargo test --manifest-path native/price-xlsx/Cargo.toml --locked` **14/14 通过**；
  `cargo test --manifest-path desktop/src-tauri/Cargo.toml --locked` **3/3 通过**。

## 构建与产物

- 使用 `dist/build-0.1.46.sh`（与 `build.ps1` 同一顺序调用同一套脚本：`release_source.py` → `version.py check`
  → `prepare_payload.py` → `verify_payload.py` → 归档 `node_modules` → `npm ci` → `npm run build -- --bundles nsis`
  → 复制安装包与摘要 → `release_source.py` 输出来源 → `build_updates.py`）。此前已确认 `build.ps1` 外层在会话
  后台命令的 120 秒上限处被强杀，故沿用脚本编排；编排方式变化不影响产物口径。脚本与日志位于 Git 忽略的 `dist/`。
- 载荷：归档旧 `app`（63.1 MB）与内置 `python`（410.1 MB），`Windows payload ready: 691 managed files`
  （较 0.1.45 多 1 项，为新增的 `toolbox_cancellation.py`）、`PAYLOAD_FRESH=OK`
  （版本 0.1.46、helper 与 Rust 源码一致、运行时 Python 3.11.15）。
- NSIS / LZMA 产出 `电力工具箱_0.1.46_x64-setup.exe`（310.65 MiB），复制为
  `ElectricityToolbox_0.1.46_windows_x64_setup.exe`，**325,738,886 字节**，

  `source-0.1.46.json` 与载荷 `manifest.json` 的来源均为
  `{commit: 426fa6c, development: false, dirty: false}`，载荷版本 0.1.46、691 项。

## 隔离安装验收结果

仅替换版本与产物路径），在 Git 忽略的 `dist/acceptance-0.1.46/` 隔离目录执行；HKCU 注册表值先保存后恢复。
退出码 `ACCEPTANCE_EXIT=0`，用时约 9 分钟。

- 全新安装：回读版本 0.1.46，清单 **14,939 项**（较 0.1.45 的 14,938 项多 1 项，对应新增模块）；
  主程序、内置 Python、载荷清单、启动器与 Rust 服务均在位。
- 覆盖升级：先装 0.1.45（回读 0.1.45），写入标记文件模拟用户数据，再用完整包覆盖；回读 0.1.46，
  标记文件内容与哈希未变。清单与全新安装**逐项完全一致**（仅全新安装独有 0 项、覆盖升级多出 0 项、内容差异 0 项）。
- 补丁实际还原：以真实 0.1.45 安装副本为基准，`clone_installation` + `apply_patch(0.1.45→0.1.46)` 后回读 0.1.46，
  清单与全新安装**逐项完全一致**（差异 0 项）。
- 安装版运行时（全新安装与覆盖升级两处均通过）：内置 Python 3.11.15 实际创建并销毁 Tk 窗口（`TK=OK`），
  导入 tkinter／openpyxl／pandas／numpy（`DEPS=OK`）；Rust 服务实际启动并输出
  `service-ready`（protocol 3，2,321,920 字节，含本轮 `cooperative` 分支）与 `service-closed`。
- 主程序仍为未签名构建（与既有发行一致，项目未做代码签名）；静默安装目录内无 `state/installed.json`，
  改以各安装目录 `payload/manifest.json` 回读版本。

## 验证边界

- 主程序未做 Authenticode 代码签名；静默安装目录中 `state/installed.json` 由首次真实运行生成。
- 协作取消的验证口径为「标记文件 → 当前批次收尾 → 退出码 130」：由 `test_tasks` 的进程级用例、
  `test_rust_service` 的真实服务用例（含私有批量上传与市场表更新）覆盖；**未**在真实生产账号的登录、
  上传或 WPS 写入流程中实际点取消验证，真实取消只保证不中断已开始的单次提交，是否重复提交由各脚本
  自身的提交与核验逻辑决定。
- `COOPERATIVE_TOOLS` 覆盖 10 个工具；其余工具（如登录类动作）仍按原方式立即终止，行为未变。
- 上网电量尾差清理只作用于「清远 实际上网电量（万千瓦时）」标题之后 25 行内的数值单元格，且仅在
  文件名以 `上网电量汇总_` 开头的「汇总」表生效；字符串与已有一位小数的值保持原样。未用生产旧表做端到端回归。
- `docs/reviews/code-review-2026-11-18.md` 中 R1、R2、R5、R6、R7 仍未修改，不在本版。
- `docs/reviews/recovery-needed-2026-11-16.md` 所列日报安全与 Windows 建议批次改动仍未重做，**不包含在本版**。
