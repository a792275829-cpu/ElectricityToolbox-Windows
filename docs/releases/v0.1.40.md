# Windows v0.1.40 发行验收记录

用户可见变化以根目录 `CHANGELOG.md` 为唯一来源；本文件记录本轮的验收范围、环境与结果，
实现细节和验证证据在此留档，不改写已发布版本的历史记录。

## 范围

- 源码：`main` 上 v0.1.39 之后的 7 个修改文件：WPS 写入工具的来源链接刷新与工作表列表联动、`覆盖非空单元格` 写入选项及配置持久化、写入回读核对，以及 3 份针对性测试；另有本轮的版本元数据、更新日志与发行记录改动。
- 用户可见变化：修复 WPS 来源链接刷新和名称显示，刷新链接时自动选择金山文档来源，添加／编辑区域的工作表下拉框同步读取最新列表；WPS 写入工具新增“覆盖非空单元格”勾选项（默认勾选），取消后仅写入空单元格，保存选项并按实际写入内容回读核对。
- 发行产物：`ElectricityToolbox_0.1.40_windows_x64_setup.exe`、同名 `.sha256`、`updates-0.1.40/` 内的增量补丁与 `windows-update-manifest.json` 及其摘要、`source-0.1.40.json`。

## 环境

- Windows 10 / 11 x64；Windows PowerShell 5.1 用于构建入口，Git Bash 用于只读检查。
- `.python-version` 为 3.11.15；独立 CPython `.toolbox/standalone-python` 与测试用 `.venv/Scripts/python.exe` 均为 3.11.15，三者一致。
- Rust / cargo 1.99.1、Node 22.22.2、NSIS makensis。
- 旧版基线：本地留存的 `ElectricityToolbox_0.1.37_windows_x64_setup.exe`、`ElectricityToolbox_0.1.38_windows_x64_setup.exe` 与 `ElectricityToolbox_0.1.39_windows_x64_setup.exe`。
- 复用 v0.1.39 构建后的 release 缓存，不重复清理；测试使用统一入口的隔离数据目录；不执行生产账号登录、真实上传或业务工作簿写入。

## 结果与证据（发行前检查）

- `version.py check --tag v0.1.40 --require-notes` 输出 `v0.1.40`；package.json、tauri.conf.json、package-lock.json、Cargo.toml、Cargo.lock 五处版本一致。发布说明由 `version.py check --release-notes` 导出到 `dist/v0.1.40-release-notes.md`（1,842 字节），内容为本版 2 条变更与通用安装说明。`[Unreleased]` 草稿已整理为 0.1.40 正式条目，无重复维护。
- `git -c core.whitespace=cr-at-eol diff --check` 通过（仓库元数据文件本身为 CRLF）。待提交文件均为源码、测试、文档与版本元数据，无凭据、登录态、业务工作簿或构建产物。新增的 3 份 WPS 测试均显式声明 `TOOLBOX_TEST_TAGS`（`()` 或 `("gui",)`），统一入口以 `unittest discover` 自动收录。
- `tools/run_tests.py full --strict`：155 个模块中 **150 个通过、跳过 0，用时 658.0 秒**；失败 5 个模块。这是首次全量运行的真实结果，不表述为一次性全绿。
  - `toolbox:test_toolbox` 为**真实回归**：`test_wps_writer_exports_runtime_config_with_schema` 的期望配置字典未包含本版新增的 `overwrite` 字段，而 `normalize_runtime_config` 会补出默认值 `True`，导致往返断言失败。核对 `toolbox_wps_config.py` 后确认产品代码的导出／导入均正确持久化该字段；已在测试期望字典补 `"overwrite": True`，并追加一条 `overwrite=False` 导出再导入仍为 `False` 的往返断言。
  - 其余 4 个 desktop 模块（`test_windows_delta`、`test_windows_update`、`test_windows_update_build`、`test_windows_update_helper`）traceback 全部指向会话注入的 `sitecustomize.py::_check_bulk_delete_guard`，拦截临时目录清理与 `path.unlink()`，与上两轮同一环境干扰。
- 对这 5 个模块用统一入口 `--module` 集中复跑：**5/5 通过、跳过 0，用时 66.5 秒**。未因复跑通过而改写首次全量结果，也未重复整轮。
- Rust：`cargo test --manifest-path native/price-xlsx/Cargo.toml --locked` 13/13 通过；`cargo test --manifest-path desktop/src-tauri/Cargo.toml --locked` 2/2 通过（debug 编译 1 分 18 秒）。复用 0.1.39 的缓存，未出现 build script 读取插件权限文件失败。
- `start_source_test.ps1 -Smoke` 输出 `TOOLBOX_SMOKE=OK`、`TOOLBOX_DEPS=OK`。
- 接口一致性：`wps自动/wps_excel_to_kdocs_gui.py` 的 `write_to_wps(..., overwrite=True)` 已同时被 GUI 写入线程与 `toolbox/workflows.py` 调用，配置持久化与按 `expected` 回读核对均已同步。

## 构建与产物

- 正式构建 `build.ps1 -PythonRoot .toolbox/standalone-python` 返回 `BUILD_EXIT=0`，用时 **37 分 42 秒**。Cargo release 编译 4 分 20 秒（复用 0.1.39 的缓存）；NSIS / LZMA 打包与增量补丁的多基线静默安装、逐文件哈希及实际还原验证仍是主要耗时。
- 采用前台长时执行（10 分钟超时自动转后台且不终止进程）并在无会话注入环境运行，避免 2 分钟截断与守卫拦截；未清理缓存、未修改构建脚本、未绕过构建脚本内的安全逻辑。
- `source-0.1.40.json` 与载荷 `manifest.json` 的 `source` 均为 `{commit: c9912aea…, development: false, dirty: false}`；载荷版本 0.1.40、693 个受管文件、`PAYLOAD_FRESH=OK`。
- 完整安装包 325,739,674 字节（310.65 MiB），SHA-256 `912ab516c1a09e45e45c5338535fd7ad69482101a846ec06d3a65136bc5f5ae0`；`updates-0.1.40/` 含 0.1.39→0.1.40 补丁 2,892,056 字节、补丁摘要、`windows-update-manifest.json`（3,197 字节）及索引摘要。索引沿用 6 条历史补丁 URL 并新增 1 条指向 v0.1.40，共 7 条直达路径。
- `dist/windows` 下 9 个历史与 2 个本轮相关的 `.sha256` 共 11 个，按内容重算逐一通过（`ALL_OK=True`）。仓库摘要文件为 CRLF，直接用 `sha256sum -c` 会把尾随 `\r` 当作文件名的一部分，属工具口径差异，不是产物问题。

## 隔离安装验收结果

验收脚本 `dist/acceptance_0_1_40.py` 复用项目自身的安装、清单与补丁模块（基于 `dist/acceptance_0_1_38.py`，仅替换版本与产物路径），在 Git 忽略的 `dist/acceptance-0.1.40/` 隔离目录执行；HKCU 注册表值先保存后恢复，不涉及用户日常安装目录。退出码 `ACCEPTANCE_EXIT=0`。

- 全新安装：回读版本 0.1.40，清单 14,941 项；主程序、内置 Python、载荷清单、启动器与 Rust 服务均在位。
- 覆盖升级：先装 0.1.39（回读 0.1.39），写入 `state/acceptance-marker.json` 模拟用户数据，再用完整包覆盖；回读 0.1.40，标记文件内容与哈希未变。**清单与全新安装逐项完全一致**（仅全新安装独有 0 项、仅升级目录独有 0 项、内容差异 0 项）。
- 补丁实际还原：以真实 0.1.39 安装副本为基准，`clone_installation` + `apply_patch(0.1.39→0.1.40)` 后回读 0.1.40，清单与全新安装逐项完全一致。
- 安装版运行时：内置 Python 3.11.15 成功导入 tkinter／openpyxl／pandas／numpy 并实际创建、销毁 Tk 窗口（`TK=OK`、`DEPS=OK`）；Rust 服务实际启动，输出 `service-ready`（protocol 3）与 `service-closed`，全新安装与覆盖升级两处均通过。
- 三处安装目录的 `payload/manifest.json` 版本均为 0.1.40，来源提交均为 `c9912aea…`、`dirty=false`。
- 主程序 Authenticode 状态为 `NotSigned`（与既有发行一致，项目未做代码签名）；`state/installed.json` 由首次真实运行生成，静默安装目录内不存在，改以三处 `payload/manifest.json` 回读版本。
