# Windows v0.1.42 发行验收记录

用户可见变化以根目录 `CHANGELOG.md` 为唯一来源；本文件记录本轮的验收范围、环境与结果，
实现细节和验证证据在此留档，不改写已发布版本的历史记录。

## 范围

- 源码：`main` 上 v0.1.41 之后的 85 个修改文件、41 个删除文件与 10 个新增文件。主线是 Windows 单平台收敛：移除 macOS 启动入口（4 个 `.command` 与 `package_macos.command`、`setup_macos.command`）、macOS 安装与打包实现（`desktop/python/auto_install.py`、`installer_image.py`、`remote_updater.py`、`source_debug.py`，`packaging/tauri/build_dmg.py`、`build_pkg.py`、`build_icons.py`、`build_update_test.py`、`build_updates.py`、`install_user_app.py`、`pkg-scripts/`、`validate_installer.py`、`requirements-macos.lock`）、`Info.plist`、`icon.icns`、签名更新夹具与对应测试，以及 macOS 专用浏览器／OCR 分支（`wps自动/启动WPS专用Chrome.command`、`gd_pdf_tool/recognize_image_labels.js`）。
- 业务修复：集团省内数据生成的 C2 公式来源与导入回读、Windows 工作簿外部修改漏检、早报工作表尺寸声明、交易系统历史模板日期编码、WPS 仅填空白模式的公式读取、安装版升级遇本地修改的备份与乱码、WPS 接口超时与排队提示、后台任务结束提示。
- 兼容修复：Chrome 156 会把 `--user-data-dir` 参数加上引号，并在启动后把主进程交接给新进程，原以无引号匹配与 `Popen` 进程号判活的逻辑因此认不出自己的浏览器。改为同时匹配带引号形式，并在 CDP 就绪后采纳实际持有配置的主进程；进程枚举失败按“尽力而为”处理，不阻断浏览器启动。
- 测试与文档：新增 `tools/unittest_worker.py`、`电力工具箱/tests/test_group_upload_safety.py`、`电力工具箱/tests/test_windows_ocr_pipeline.py`；新增 7 份评审记录；同步 `AGENTS.md`、`README.md`、`docs/` 下的结构、架构与迁移说明。
- 用户可见变化：`CHANGELOG.md` 的 0.1.42 条目共 9 条，草稿已全部整理，无未完成条目残留。
- 发行产物：`ElectricityToolbox_0.1.42_windows_x64_setup.exe`、同名 `.sha256`、`updates-0.1.42/` 内的增量补丁与 `windows-update-manifest.json` 及其摘要、`source-0.1.42.json`。

- `version.py check --tag v0.1.42 --require-notes` 输出 `v0.1.42`；package.json、tauri.conf.json、package-lock.json、Cargo.toml、Cargo.lock 五处版本一致。发布说明由 `version.py check --release-notes` 导出到 `dist/v0.1.42-release-notes.md`（3,326 字节），含本版 9 条变更与通用安装说明。`version.py set` 因草稿中存在空行未自动清理未发布条目，已按仓库约定手工重建：正式条目置顶、历史 38 个版本条目原样保留、无边界的重复草稿。
- `git -c core.whitespace=cr-at-eol diff --check` 通过（仓库元数据文件本身为 CRLF；`wps自动/wps_excel_to_kdocs_gui.py` 由 CRLF 归一为 LF，与其余 Python 源文件一致）。待提交 142 个文件均为源码、测试、文档与版本元数据，无凭据、登录态、业务工作簿或构建产物。
- 删除项引用核对：在 `desktop/python`、`desktop/src-tauri/src`、`电力工具箱`、`tools`、`packaging` 中搜索 `auto_install`、`installer_image`、`remote_updater`、`source_debug`、`build_dmg`、`build_pkg`、`build_icons`、`validate_installer`、`release_index`、`install_user_app`、`prepare_tk`、`signed-update`、`recognize_image_labels.js`、`package_macos`、`setup_macos`，源码中无残留导入或调用（仅历史发行记录与构建产物快照包含旧字符串）。
- `tools/run_tests.py full --strict` 首次运行：**154 个用例中 153 个通过、跳过 0，用时 765.0 秒**，失败 1 个模块 `desktop:test_rust_service`（2 个断言失败 + 1 个临时目录清理 `PermissionError`）。这是首次全量运行的真实结果，不表述为一次性全绿。
- 该失败单独复跑稳定重现；在 HEAD（v0.1.41，提交 `c2f821d`）的 `git worktree` 独立检出中用同一服务二进制复跑，结果完全一致，确认不是本轮改动引入的回归。定位过程：Chrome 156 会把 `--user-data-dir` 参数加引号，且启动后把主进程交接给新进程、由启动器以退出码 0 结束；原实现只匹配无引号形式、并按 `Popen` 进程号判活，既找不到自己的浏览器，也把已打开的窗口判为已退出，启动等待循环还可能因启动器退出而提前报错。探针实测：`--user-data-dir="C:\..."` 的主进程存在，但 `discover_managed_chrome_pid()` 返回 `None`，记录的 pid 在 2 秒后已不存活。
- 修复后：`is_managed_chrome_command` 同时匹配带引号形式；CDP 就绪后采纳实际持有配置的主进程并写回状态；进程枚举失败按“尽力而为”处理，不阻断启动。针对性复跑 `test_rust_service`、`test_wps_login_status`、`test_wps_api_recovery`、`test_wps_async_dialog`、`test_wps_windows_compat` **5/5 通过、92 个用例、跳过 0**。
- 修复后重跑 `full --strict`：**154/154 通过、跳过 0，用时 642.3 秒**，无失败模块。
- Rust：`cargo test --manifest-path native/price-xlsx/Cargo.toml --locked` **13/13 通过**；`cargo test --manifest-path desktop/src-tauri/Cargo.toml --locked` **3/3 通过**（本版新增“界面关闭后重开提示清理状态”用例）。
- `start_source_test.ps1 -Smoke` 输出 `TOOLBOX_SMOKE=OK`、`TOOLBOX_DEPS=OK`。
- GitHub 发布通道：`api.github.com` 凭据可用，仓库有 push 权限；最新公开 Release 为 `v0.1.41`（draft=false、11 个附件），v0.1.42 尚不存在。

## 隔离安装验收结果

验收脚本 `dist/acceptance_0_1_42.py` 复用项目自身的安装、清单与补丁模块（基于 `acceptance_0_1_38.py`，仅替换版本与产物路径），在 Git 忽略的 `dist/acceptance-0.1.42/` 隔离目录执行；HKCU 注册表值先保存后恢复，不涉及用户日常安装目录。退出码 `ACCEPTANCE_EXIT=0`。

- 全新安装：回读版本 0.1.42，清单 **14,938 项**；主程序、内置 Python、载荷清单、启动器与 Rust 服务均在位。
- 覆盖升级：先装 0.1.41（回读 0.1.41），写入标记文件模拟用户数据，再用完整包覆盖；回读 0.1.42，标记文件内容与哈希未变。清单与全新安装的差异为：仅全新安装独有 0 项、内容差异 0 项，**覆盖升级目录多出 4 个旧文件**（`payload/app/desktop/python/auto_install.py`、`installer_image.py`、`remote_updater.py`、`gd_pdf_tool/recognize_image_labels.js`）。这是完整安装包覆盖升级不清理源码中已移除文件的既有行为；这 4 个文件不在 0.1.42 载荷清单内，不影响启动与功能。
- 补丁实际还原：以真实 0.1.41 安装副本为基准，`clone_installation` + `apply_patch(0.1.41→0.1.42)` 后回读 0.1.42，清单与全新安装**逐项完全一致**（差异 0 项），说明补丁包含被移除文件的删除动作。
- 安装版运行时（全新安装与覆盖升级两处均通过）：内置 Python 3.11.15 实际创建并销毁 Tk 窗口（`TK=OK`），导入 tkinter／openpyxl／pandas／numpy（`DEPS=OK`）；Rust 服务实际启动，输出 `service-ready`（protocol 3）与 `service-closed`。
- 主程序 Authenticode 状态为 `NotSigned`（与既有发行一致，项目未做代码签名）；`state/installed.json` 由首次真实运行生成，静默安装目录内不存在，改以三处 `payload/manifest.json` 回读版本。
