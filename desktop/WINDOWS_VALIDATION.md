## 性能对照

使用同一个合成工作簿（20,000 行 × 10 列，包含中文、日期和数值），Python、修改前 Rust、修改后 Rust 交替运行 5 次。每次都比较全部 200,000 个单元格值与数字格式。

| 实现 | 完整读取并物化单元格的中位耗时 |
| --- | --- |
| Python/openpyxl | 1.704 秒 |
| 原 Rust 后端 | 1.726 秒 |
| 优化后 Rust 后端 | 1.415 秒 |

此样本中 Rust 修改后耗时减少约 **18.0%**，相对 Python 耗时减少约 **17.0%**。优化是将已经构造好的元数据移入 JSON 结果，消除坐标字符串和数据映射的重复复制；业务计算与协议字段未改变。原始记录位于本机构建目录 `.toolbox/windows-excel-comparison.json`。

页面连续切换中位耗时 57.086 ms，最大 1265.202 ms；包含页面初次加载和异步依赖准备，不能解读为所有操作都在 60 ms 内完成。测量时存在后台构建负载，以上是本机样本，不是跨机器保证。初次非交替对照受编译负载干扰，未采用其结果推断收益。

另一个启动优化是 Windows 正常运行时不创建隐藏 WebView2，诊断窗口按需创建。原来的页面懒加载、批量日志刷新、任务范围内 Rust 会话和有界缓存继续保留。

复现命令见 [Windows 使用说明](WINDOWS.md)。`benchmark_excel.py` 还支持 `--baseline-binary <旧版原生助手.exe>`，用于在同一机器交替比较修改前后。
